Jo — tohle je důležitý detail. Jestli vidíš své větve, ale při jejich porovnání GitHub neukazuje žádné změny, problém pravděpodobně není v tom, že bys nenašla správné tlačítko. GitHub totiž pull request vytváří právě na základě rozdílu mezi dvěma větvemi.

Nejčastější jsou tyto situace:

Změny nejsou commitnuté.
Soubor jsi upravila, ale změna zůstala jen lokálně v počítači. Musíš udělat:

git add .
git commit -m "Popis změny"
git push

Teprve potom se změna objeví na GitHubu.

Změny jsou v jiné větvi, než kterou porovnáváš.
Třeba jsi pracovala ve větvi oprava, ale na GitHubu se díváš na main nebo jinou větev.
Tvoje větev je ve skutečnosti úplně stejná jako main.
V tom případě GitHub správně nemá co ukázat. Pull request dává smysl jen mezi větvemi, mezi nimiž existuje nějaký rozdíl.
Změny jsi udělala ve svém počítači, ale ještě jsi je neposlala (push) na GitHub.
To je velmi časté u začátečníků.
Pojďme zjistit, která varianta je u tebe

Pokud máš otevřený terminál ve složce projektu, napiš mi prosím výstup těchto tří příkazů:

git status
git branch
git log --oneline --all -5

Klidně sem zkopíruj úplně všechno, co ti to vypíše. Podle toho ti přesně řeknu, kde se ty změny nacházejí a co máš zmáčknout/udělat dál.

A mimochodem: ten návod na Naucse popisuje správný princip, ale rozhraní GitHubu se mezitím změnilo, takže se nemusíš divit, že obrazovka u tebe nevypadá přesně stejně. GitHub dnes umožňuje při vytváření PR ručně zvolit base repository + base branch a head fork + compare branch.
